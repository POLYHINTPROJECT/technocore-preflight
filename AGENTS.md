# Technocore — Project Operating Instructions

Permanent rules for all work in this workspace. Hermes loads this file automatically.

## PROJECT PURPOSE

We are exploring and then building one original public product around Technocore.

## PRODUCT PRINCIPLES

- Free
- Public
- No login
- No signup
- No wallet
- No payment
- No artificial engagement
- No token/airdrop farming as the product
- Must be genuinely useful without the reward narrative
- Prefer products whose value survives a small ecosystem

## ORIGINALITY

- Do not clone existing Technocore projects.
- Do not make another DID onboarding wizard.
- Do not make another contribution-proof flow.
- Do not make another offline did:key verifier.
- Do not make another room explorer/dashboard/chat viewer.
- Do not make another generic receipt/evidence tool.
- Do not make another Kibble-style task board.
- Do not make another lobby check-in/farming agent.
- Before committing to an idea, research the current ecosystem and explicitly check for overlap.

## TECHNOCORE

- Treat primary Technocore documentation/source as authoritative.
- Distinguish verified facts from inference.
- Respect rate limits and ephemeral/ring-buffer semantics.
- Do not create unnecessary network traffic.
- Never fabricate protocol guarantees.

## AGENT WORKFLOW

- Research before architecture.
- Architecture before implementation.
- Use checkpoints and tests.
- Do not preserve a weak idea merely because work has already been done.
- Prefer small validated steps over one giant implementation.
- Turn genuinely reusable successful workflows into verified skills only when justified.
- Preserve important research findings in project files, not only conversation memory.

## SECURITY

- Never expose or commit private keys, passphrases, tokens, credentials, or secret environment files.
- Our Technocore DID is public; its private identity material is not.
- Do not access unrelated private identity directories unless explicitly required.

## TOOLING

- Prefer native Hermes tools first.
- Install MCPs only when a concrete project need justifies them.
- Use web research with source discipline.
- Keep tool surface minimal.
